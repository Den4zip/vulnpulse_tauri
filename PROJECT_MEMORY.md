# VulnPulse Tauri — состояние проекта

Обновлено: 2026-11-21. Источник: запрос пользователя продолжить разработку, [PLAN.md](PLAN.md), локальные проверки и Windows CI.

## Принятые решения

- Пользователь выбрал новый проект на Tauri/Rust/TypeScript с сохранением лучших функций и дизайна. Tauri заменяет Electron. Рабочая папка: `D:\проект\vulnpulse-tauri`.
- Основной план — [PLAN.md](PLAN.md), правила — [AGENTS.md](AGENTS.md). Уточнения библиотек, формата Vault и методики риска в плане являются будущими решениями, а не проверенной реализацией.
- Перенесены три подтверждённых правила: upgrade сохраняет установку, перенос создаёт новую; пересчёт не меняет ручной статус; legacy-заметки/SLA назначаются finding только отдельным действием.

## Фактическое состояние

- Локальные проверки и Windows CI для этапа 0 пройдены. [PR №1](https://github.com/Den4zip/vulnpulse_tauri/pull/1) влит в `main` с коммитом основы `4a18977`. Последующие исправления Windows CI вошли в `develop`. Node.js 24.21.0 и Rust 1.100.0 зафиксированы в проекте.
- Этап 1 реализует Welcome Hub и учебный каталог с 24 записями. Rust выполняет поиск без учёта регистра, фильтры критичности, источника и KEV, стабильную сортировку, пагинацию и сводку в SQLite. Версионированная миграция 002 добавляет карточки и исходные записи. В карточке видны дата публикации, дата изменения, дата получения и исходная учебная оценка CVSS. Команды каталога доступны основному окну. Интерфейс получает генерируемые DTO.
- В оболочке Mint используются Tailwind CSS, локальные компоненты на основе шаблонов shadcn/ui, Lucide и Zustand. Фильтры и страница сохраняются при возврате в каталог. На узком экране карточка занимает всю ширину. Атрибуция и лицензии доступны в диалоге «О дизайне». Методика приёмки и масштабы снимков зафиксированы в [проверках каталога Windows](docs/windows-stage-1.md).
- Экран демонстрационного каталога читает две синтетические записи через `list_demo_catalog`. Rust проверяет лимит, выполняет SQLite вне async executor и ограничивает параллелизм одним запросом. SQL-миграция включена в приложение и применяется транзакционно с проверкой SHA-256. Временная SQLite создаётся в памяти, типы TypeScript генерируются из Rust через ts-rs.
- Команда внесена в Tauri AppManifest и разрешена capability основного окна. Установлены CSP и ограничения навигации. Добавлены Windows workflow с NSIS, Edge WebDriver smoke с отдельным профилем и тестовый конфиг для проверки отказа IPC. Команды и методика проверок — в [заметках этапа 0](docs/windows-stage-0.md).
- История прежнего репозитория сохранена в `references/legacy-history.bundle`, включая `c44d73605985dff7b9c8fadc929a06efa3c6c068`. Git сообщил полную историю и успешную проверку bundle. Пользовательские БД, секреты и игнорируемые файлы туда не входят.
- Старый проект сохранён. По последней проверке его ветка `develop` была чистой и на один коммит впереди локального `origin/develop`. Отправка исправления Electron CI ранее была прервана.

## Проверки и ограничения

- Прочитаны локальные требования, дизайн, концепция, модель, Vault, CSS, контракты и тестовые сценарии. Просмотрено сохранённое превью Mint. Ссылки на Figma и сведения о лицензии происходят из исследования старого проекта; внутренние слои Figma заново не получены.
- Документы Tauri об архитектуре, разрешениях, WebDriver и окружении проверены в официальных источниках; ограничения custom commands сверены через Context7.
- Проверены 4 Markdown-документа, 34 локальные ссылки внутри пакета, парность блоков кода, отсутствие символов ошибки декодирования и SHA-256/размеры 9 сохранённых материалов — ошибок нет. Проверены `git bundle verify`, восстановление в отдельный bare-репозиторий, `git fsck --full` и точное совпадение HEAD с исходным коммитом. Архив содержит полную Git-историю; восстановленное приложение не собиралось. Контрольные суммы находятся в `references/manifest.json`.
- На Windows 11 Pro x64 установлены Microsoft C++ Build Tools и Windows SDK. После чистого `npm ci` прошли проверка типов, линтер, два frontend-теста, проверка документации и сборка интерфейса. Прошли Rust fmt, Clippy, шесть Rust-тестов, генерация и проверка DTO.
- Собран `src-tauri/target/release/bundle/nsis/VulnPulse_0.1.0_x64-setup.exe` (210,4 МиБ) со встроенным офлайн-установщиком WebView2. В Edge WebDriver 157.0.4341.60 пройдены оба desktop-сценария: релиз загрузил записи из SQLite и отклонил неверный лимит, отдельная сборка отклонила IPC для окна без разрешения. Релиз также проверен через Tab и Enter. Для запуска использован системный PATH без Node.js. Отдельно проверен debug-бинарник с готовым локальным Vite после принудительного пересчёта зависимостей.
- [Первый прогон Windows CI](https://github.com/Den4zip/vulnpulse_tauri/actions/runs/44605822179) прошёл frontend, Rust, контракты, сборку и установку NSIS. Проверка установленного экземпляра остановилась по 30-секундному тайм-ауту WebDriver. Desktop-тест теперь отдельно запускает приложение, ждёт готовности WebView2 и затем подключает драйвер. В ошибке WebDriver указаны метод и путь запроса.
- [Второй прогон](https://github.com/Den4zip/vulnpulse_tauri/actions/runs/44627395276) также собрал и установил NSIS. Приложение осталось запущенным, но WebView2 на `windows-2025` так и не открыл loopback-порт. Образ переведён на `windows-2022` для повторной проверки по аналогичному [отчёту runner-images](https://github.com/actions/runner-images/issues/14738).
- [Первый прогон на windows-2022](https://github.com/Den4zip/vulnpulse_tauri/actions/runs/44631478129) установил релиз, запустил WebView2 131.0.2903.86 и отобразил экран. После Tab фокус остался на странице, поэтому проверка IPC в CI теперь активирует кнопку стандартным кликом WebDriver. Локально NSIS установился во временный каталог, чтение SQLite в установленном приложении прошло, тестовая установка удалена.
- [Итоговый Windows CI](https://github.com/Den4zip/vulnpulse_tauri/actions/runs/44634242381) на коммите `5e19511` прошёл полностью. Чистый checkout собрался, установщик NSIS установился, положительный IPC в установленном релизе и отказ окну без разрешения проверены, артефакт Windows x64 загружен.
- Покрытие Rust сформировано с cargo-llvm-cov 0.9.1, совместимым с расположением тестовых файлов Cargo 1.100 на Windows. Сводка unit-тестов: 61,24% строк, 65,82% LLVM regions и 54,55% функций. IPC и application service проверены через WebView2 отдельно от отчёта покрытия.
- Для этапа 1 пройдены TypeScript typecheck, линтер, два frontend-теста, сборка Vite, docs check, форматы и Clippy Rust, девять Rust-тестов и проверка генерации DTO. Отчёт Rust unit-тестов даёт 61,24% строк по crate и 95,26% строк в инфраструктуре. Обработчик ошибок покрыт frontend-тестами. Сценарии интерфейса и IPC запускаются отдельно в WebView2.
- Отдельная debug-сборка этапа 1 в WebView2 157.0.4341.60 отклонила все три catalog-команды при отсутствии разрешений. Установочный сценарий использует временный профиль WebView2. Для фонового окна тест активирует DOM-кнопки и использует события WebDriver и DevTools для проверки клавиатуры.
- Релизный WebView2 загрузил каталог из SQLite, выполнил поиск, фильтры, сортировку, переход между страницами, показ карточки и возврат фокуса. Сохранены шесть снимков в локальной папке `.tools/catalog-screenshots`, включая 1280×800 при моделировании 100/125/150%, 1024×768, крупный счётчик и полноширинную карточку. Локальный профиль Windows сохранял текущий системный DPI.
